## Scope audit for the remaining inventory

- `CheckBS2CommandStatus`: the differing `stw` relocates to `CacheCommandComplete`. All its reads and writes are inside this function. `BS2NANDCallback` changes `NandPending`, already volatile, rather than `CacheCommandComplete`. The adjacent partition count is disc table data read after DVD completion. No new shared completion declaration has been established here.
- `update_friendinfo`: both differences are `addi` arguments for `wcsncpy`, pointing to the friend name and this scene's editable name. They are not scalar shared-state accesses. No qualifier trial is justified.
- Four `collectTitles*` functions: the repeated difference is `++*titleCount`, local accumulated blocks, and `secondUsage[0]`. The source exposes these through caller parameters, with no proven shared field/global definition at the accesses. Changing the pointer parameter type or a use-site cast would not be lever 19. `collectTitlesByChannelOrder` also has three address/register differences.
- `flushSaveDataAndMountSD`: swapped loads are `System::Arg::mpSaveDataManager` and `mpMem2App`, stable manager/heap pointers. Asynchronous work starts after the call arguments are loaded. There is no callback-written completion flag at these accesses.
- `scanAP`: case 9 loads `mpMainLayout` and `unk_0x918`, the animation index set by scene transitions. Its AP worker writes `mAPScanList`, not either reordered field. The latter is not evidence for qualifying the former.
- `AOSSi_WLANConnect`: only the IP-config `memset` destination/size argument order differs. The separate `AOSSi_cancel_flag` is genuinely shared with `iplAOSSThread`, so a global-definition trial with the matching extern in AOSS.c will test whether it affects this function. The mutable config itself is handed to synchronous NCD calls and contains no demonstrated completion field.
- `ATERMBuildEncryptedMessage`: only the key-parameter save and `memset` destination move exchange places before the first call. No global/field access in that block.
- `CHANSVmConvertToFloatFromStr`: the reordered store initializes the local `end` pointer passed to synchronous `strtoull`/`strtod`; the compare checks the input object type. Neither is a worker completion flag. No volatile stack workaround.
- `VmDateDtor`: reorders read-only day/month string-table loads and a `snprintf` stack argument. No mutable shared state at the difference.
- `NHTTPi_strnicmp` and `NHTTPi_compareToken`: differences precede the first character load and only materialize constants 0 and 0x5a. No declaration to qualify.
- `NHTTPi_compareTokenN_HdrRecvBuf`: reorders ASCII bound constants, a sign extension and a local limit decrement. The response buffer is already received; no reordered memory access identifies a shared flag.
- `SOGetSockName`: the difference is the first memcpy before IOS_Ioctl, reading caller-owned `addr->len`. The later IOS reply shares the SOSockAddr type, so test its length field unconditionally across all including units, while checking for extra validation reads or regressions.
- The tail-window scan also returned `kbdProcMod`, `KBDSetModState`, and `kbd_led_handler`. Manual ctxdiff review excludes them from pure epilogue order: the first two differ in address/value register allocation, and the handler differs in branch polarity and constants. Their Ghidra/source paths were inspected; no claim that they are scheduling-only candidates.
- `pfd_sddrv_finalize` mixes one register difference with callback-state store ordering. Its media, device, disk and drive fields are shared with SD insertion/removal callbacks. Test the individual real field declarations and the paired media flags. These types are local to sd_drv.c.
