## Raw-buffer audit and trials

- `OSFont.c:Decode` reads the on-disk Yay0 header: decompressed length at
  0x04, link-table offset at 0x08, literal-stream offset at 0x0C. `GetFontSize`
  checks the Yay signature and reads the same length. The other cast reads a
  variable-position mask word. These are big-endian serialized data accesses,
  not accesses to an opaque in-memory object. Retained under the task's explicit
  file-header exception. No existing Yay0 struct appears in the matching headers.
- `rvl_dec.c` reads Yaz/ASH serialized headers and variable-position bitstream
  words. The ASH workspace accesses address 16-bit Huffman-tree nodes and a
  shared stack in an existing byte array; they are not hidden object members.
  Its assembly uses the same 0x7FE/0x1FFE tree strides. All listed C casts are
  in non-MWCC fallback branches; the accepted 43U output comes from the existing
  assembly paths. Retained: inventing a struct or changing `work` would violate
  the requested type/layout/expression freeze, and the 43U gate could not
  validate the excluded fallback code. No assembly is added or changed.
- `pf_entry.c` uses `p` as a byte cursor into `PF_DIR_ENT.long_name`. Each LFN
  entry contributes 13 UTF-16 code units, assembled from 10 + 12 + 4 bytes.
  The +0x1A store terminates the following code unit; it is an array index,
  not a distinct struct field.

| Trial | Result |
| --- | --- |
| KPAD evidence-backed field and parameter renames | Entire object byte-identical to baseline; pool identical |
| CDB existing private members and database-state names | All sections except `.strtab` byte-identical; `.strtab` only renumbers compiler `@NNNN` local symbols; pool identical; allocation/free ctxdiff 0 |
| LFN `p_ent->long_name[ordinal * 13] = 0` | Rejected: 135 instructions versus 136, extra live ordinal and changed registers/prologue |
| LFN `((pf_u16*)p)[13] = 0` | Accepted: entire object byte-identical; 136/136 instructions, ctxdiff 0 |

- LFN locals `p` -> `nameSegment`, `q` -> `nameChar`, `q_after` -> `nameEnd`:
  the source assigns the first cursor from `long_name` plus the LFN ordinal,
  then uses the other two to scan UTF-16 code units for the terminator and
  validate 0xFFFF fill. Their types and declaration order are unchanged.
  The accepted array access uses the existing cursor into `long_name` and
  preserves the store width and address. It does not invent a segment struct.
