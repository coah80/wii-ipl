## Retained constraints

- Enum bounds retain the original unsigned types. Dropping those conversions changes the handling of negative VM arguments or selects different comparisons.
- `VmGetStrFromObjHdr` and `VmGetIntFromObjHdr` are functions in `CHANSVm.c`. The latter follows a payload pointer to its length; it does not read the inline integer value. Their extra null checks changed bytes at the tested raw-access sites, so those trials were reverted. Direct member access was retained where it matched.
- `Pane::GetParent()`, shorter pointer-result tests, Color conversion chains, the nested float-sign ternary, and the save-data empty alignment branch remain where the compiled object changed. Even changes limited to compiler-generated names in `.strtab` were rejected.
- The remaining `type = 5` in `CHANSVmGetEnumedType` is the conversion-table category shared by object/class/method references. `CHANS_VM_TYPE_INDEX_REF` has the same numeric value but the wrong meaning there.
- Other retained literals describe bytecode fields, blob packing tags, scalar widths, indexes, and allocation layout with no suitable existing named constant. No replacement enum or shared layout was invented.
