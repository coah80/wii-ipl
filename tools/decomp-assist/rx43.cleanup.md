## Rejected candidates and scope decisions

- Trials 1 and 13 used an incorrect namespace or SDK spelling. The corrected scene IDs and `OS_THREAD_ATTR_DETACH` passed in 7 and 19. This SDK has no named nonblocking message flag, so 14 remains literal zero.
- Trial 50 incorrectly mapped message 446 to an enum for 454. The object comparison rejected it. Trial 53 retained only verified values; message 446 remains unchanged because no matching named entry exists.
- Trial 52 could not remove the DPD callback cast: the declared SDK parameter is `KPADCallback*`, whereas the callback is a function pointer. Changing that shared signature is outside this task.
- Trials 26, 38, and 39 changed bytes when simplifying OS thread BOOL checks. Trials 35, 36, 37, 71, 73, and 81 changed bytes when simplifying returns, self-assignment, pointer differences, or ternaries. The original expressions remain.
- The unsigned JPEG clamp accepted direct branches while retaining its range flag. The signed clamp and removing the unsigned range flag changed bytes (60 and 63). Splitting reused JPEG variables into separate lifetimes also changed bytes (91 and 92); accepted renames preserve declarations, statement order, and lifetimes.
- The FAT enums in 82 and 83 have the expected numeric values, but including their headers and using them changed object output. The source was restored.
- The HTTP receive pointer could not be implicitly initialized as `u8*` from the declared `char*` buffer (90). A `char*` cursor compiled but changed bytes (93). Changing the uppercase test from bitwise to logical conjunction also changed bytes (74).
- Remaining same-type narrow-integer casts and destination self-assignment in `pf_path.c` changed bytes in 34, 96, and 97. Accepted accessor casts were removed in 98.
- Address hover counters use `== TRUE` as a count-of-one check and must not become a general truth test. Internal PF errors have different meanings from public FA errno values; numeric-only PF aliases would not improve readability.
- Existing serialized disk offsets and the save-block offset accesses in ESMisc have no verified declared member equivalent. No new struct layout or shared-header guard was introduced.
- `math_types.cpp`, address headers, and `iplAddressAddSel.cpp` had no suitable remaining cleanup from the requested categories. They remain byte-for-byte source-identical. The toolbar table still contains its pre-existing index 7; the animation enum defines only indices 0 through 6.
- Three casts removed from `pf_service.c` occur in its DEBUG branch. The mandated release 4.3U build validates byte preservation; a separate DEBUG configuration was not built.
- Source comments are unchanged in every touched file. A final scan of all 193 permitted files found no Ghidra or m2c placeholder identifiers. Mathematical one-letter temporaries that would require lifetime changes remain where trials rejected those changes.
