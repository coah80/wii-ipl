### CDBDatabaseSearchConditionsIsMatch

The audit trial has 64/64 instructions and two different immediates, both
addresses of `type`: source SP+0x18, target SP+0x14. Target `conditions` is
r30 and `key` is r31; there is no register swap here. The Ghidra output
agrees on the three scalar outputs and the type buffer.

A type-only capacity of four makes the frame too small, 99.875%. Five
bytes and the full remaining key capacity both reach 100%. Retain the
full capacity, `CDB_RECORD_KEY_STRING_LEN - offsetof(CDBRecordKey,
keyStrStruct.type)`, which is nine bytes. A key of at most 31 characters
can produce eight type characters plus NUL. This also avoids the old
eight-byte buffer's boundary overrun. The separate maker, game, and date
outputs retain their target stack locations. 64/64 instructions, diffs 0.
The existing maker-code pointer cast does not imply a four-byte write:
`CDBConvKeyStrToMakerCode` copies `CDB_KEYSTR_MAKER_CODE_SIZE` (two)
bytes with memcpy, so the separate `u16` output has sufficient storage.

### CDBConvKeyStrToFullPath_

The padding-free audit trial has 173/173 instructions, six stack-address
differences, and no register differences. Target key/path/location/Wii-ID
are r25/r26/r27/r28, the data base is r30, and r31 is the zero terminator.
The target's two epoch buffers start at SP+0x78 and SP+0x88. Existing API
helper calls preserve the instruction sequence but change those stack
locations or the frame size. Declaring the first epoch string before the
file-name buffer gives the correct order with ordinary arrays.

The file name needs 13 bytes for eight hexadecimal digits, '.', three
serial digits and NUL. The old eight-byte array was insufficient. Using
`sizeof("00000000.000")` and `CDB_KEYSTR_EPOCH_SIZE + 1` for the first
11-byte epoch string removes the invented prefix and reaches 100%.
No array exists just to occupy the removed prefix. 173/173, diffs 0.

### NCDSetIfConfig

The clean union split differs only at instructions 8 and 16: the interrupt
state is in r29 instead of target r31. The later configuration pointer
already uses r31. Moving the interrupt local to three declaration positions
does not change this. A real `RegisterUnofficialVersion` inline routine
contains the interrupt disable, version registration, flag update and
interrupt restore. It gives the interrupt local the target r31 and keeps
all 155 instructions identical. This helper performs an operation and does
not return an identity value or group unrelated storage.

### CDBRecordKeyInit

The clean audit trial differs at five array addresses, not registers.
Target maker/type/game strings start at SP+8, SP+0xc, SP+0x14. Declare game,
type, maker arrays in reverse order and use the actual string capacities.
Three bytes hold the maker plus NUL and five hold the game plus NUL.
`CDBRecordCreateAtOnce` rejects `strlen(fileType) >= 6`, so the type buffer
must hold five characters plus NUL. A preliminary five-byte type candidate
also matched but was rejected because it is too short for that caller.
The retained six-byte type buffer reaches 100%. 65/65, diffs 0.

### Address::set_err_msg

The audit trial preserves the union's pointer-to-ID default behavior and
scores 99.875%, with only the final text result in r31 instead of r30.
Separate final-text locals and an explicitly initialized ID do not fix it.

Semantic review: the only caller is `Address::entry_friend`, after
`FriendListCache::check()` returns NWC24_ERR_NETWORK, or `getLastErr()`
returns NWC24_ERR_SERVER or NWC24_ERR_FULL. `check()` stores the returned
error in `mErrCode`. The supported input domain therefore assigns the ID
in every case. The honest form has separate text and ID variables and
no default assignment, and scores 100%, 80/80 instructions, diffs 0.

Lever 10 proof for the uninitialized ID outside that domain: target
0x4890 assigns r30 the first text pointer. At 0x490c..0x4938, only error
-31 writes ID 0x19a and errors -32/-6 write ID 0x1c5. The other paths
branch to 0x493c without assigning an ID; 0x4940 passes r30 to getMessage.
This is a target-proven missing assignment, not permission to choose a
new default. The removed union manufactured a pointer-to-ID conversion
for that unsupported path. No caller behavior in the supported domain
changes. Keep this limitation visible during parent review.
